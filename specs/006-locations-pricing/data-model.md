# Phase 1 Data Model: Locations + Pricing

**Date**: 2026-08-09 | **Spec**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md)

All tables carry `org_id` (Constitution Principle VI). Money is integer minor units
(Principle III). Migrations are generated by `drizzle-kit`; the SQL below is the
*target schema* the Drizzle definitions produce, not a hand-written migration.

## Aggregate: Station (`locations` module)

**Table**: `stations`

| Field | Type | Constraints / Default | Notes |
|---|---|---|---|
| `id` | uuid PK | — | |
| `org_id` | uuid FK → `organizations.id` | NOT NULL | tenant scoping (Principle VI) |
| `name` | varchar(255) | NOT NULL | |
| `address` | text | nullable | |
| `working_status` | enum `station_working_status` (`WORKING`, `MAINTENANCE`) | NOT NULL DEFAULT `WORKING` | FR-032 |
| `is_active` | boolean | NOT NULL DEFAULT true | **effective** active state for bookability — derived from `admin_intended_is_active AND health_status != OFFLINE` (see "Effective Active State" below) |
| `admin_intended_is_active` | boolean | NOT NULL DEFAULT true | admin's manual intent (FR-004); never mutated by the connectivity monitor (FR-010) |
| `is_visible_to_clients` | boolean | NOT NULL DEFAULT false | admin toggle (FR-004); default false = soft-launch |
| `sort_order` | integer | NOT NULL DEFAULT 0 | |
| `ha_url_or_ip` | varchar(255) | NOT NULL | part of `HaConnectionConfig` VO |
| `ha_token_ref` | varchar(255) | NOT NULL | opaque `SecretStore` reference (FR-019/020) |
| `auto_lock_delay_sec` | integer | NOT NULL DEFAULT 30 | per-station; CHECK > 0 (FR-014, Clarification 2026-08-09) |
| `health_status` | enum `station_health_status` (`ONLINE`, `OFFLINE`, `UNKNOWN`) | NOT NULL DEFAULT `UNKNOWN` | FR-011 |
| `last_health_check_at` | timestamptz | nullable | FR-011 |
| `created_at` | timestamptz | NOT NULL DEFAULT now() | |
| `deleted_at` | timestamptz | nullable | soft delete (config data) |

**Validation rules**:
- `auto_lock_delay_sec > 0` (CHECK constraint) — zero/negative rejected at config time
  (Edge Case "Auto-lock delay misconfigured").
- `ha_token_ref` is opaque to `locations`; stored as-is, never decrypted by this module.

**State transitions** (`health_status`):
```
UNKNOWN ──(check ok)──► ONLINE
UNKNOWN ──(check fail #2)──► OFFLINE
ONLINE ──(check fail #2)──► OFFLINE   [publish StationHealthChanged(isOnline=false)]
OFFLINE ──(check ok #1)──► ONLINE     [publish StationHealthChanged(isOnline=true)]
```
Debounce: 2 consecutive failures to leave ONLINE→OFFLINE; 1 success for OFFLINE→ONLINE
(Clarification 2026-08-09). State transitions are the only event-publishing trigger.

`working_status` is admin-set: `WORKING ⇄ MAINTENANCE` (FR-033). `is_active` and
`is_visible_to_clients` are independent admin toggles (FR-004/005/006).

**Effective Active State**:
Bookability uses `is_active` (the *effective* flag), which is true iff
`admin_intended_is_active = true AND health_status != OFFLINE`. The connectivity
monitor mutates only `health_status` (and publishes `StationHealthChanged`); it never
mutates `admin_intended_is_active` (FR-010). On recovery (`health_status → ONLINE`),
`is_active` is recomputed: if `admin_intended_is_active = true`, the station becomes
active again; if the admin had set `admin_intended_is_active = false`, it stays inactive
(FR-010). The `admin_intended_is_active` column is updated only by admin PATCH
operations (FR-004). `is_active` is a regular column (not a generated column) updated
by the application on every health-status transition, for v1 simplicity and index
compatibility.

## Aggregate: Locker (`locations` module)

**Table**: `lockers`

| Field | Type | Constraints / Default | Notes |
|---|---|---|---|
| `id` | uuid PK | — | |
| `station_id` | uuid FK → `stations.id` | NOT NULL | |
| `name` | varchar(100) | NOT NULL | |
| `status` | enum `locker_status` (`AVAILABLE`, `RESERVED`, `AWAITING_PAYMENT`, `AWAITING_PICKUP`, `RENTED`, `MAINTENANCE`) | NOT NULL DEFAULT `AVAILABLE` | |
| `ha_lock_entity_id` | varchar(255) | NOT NULL | HA entity id for the lock actuator |
| `ha_door_sensor_entity_id` | varchar(255) | NOT NULL | HA entity id for the door sensor |
| `current_rental_id` | uuid FK → `rentals.id` | nullable | **exclusivity mechanism** (ADR-008); `AVAILABLE ⟺ NULL` |
| `created_at` | timestamptz | NOT NULL DEFAULT now() | |
| `deleted_at` | timestamptz | nullable | soft delete |

**Invariants**:
- `status = AVAILABLE` *iff* `current_rental_id IS NULL` (enforced in code; the
  critical index `idx_lockers_available` also predicates on this).
- `station_id` must reference a station in the same `org_id` (cross-org assignment
  rejected).

**State transitions** (`status`):
```
AVAILABLE ──reserve()──► RESERVED ──payment──► AWAITING_PAYMENT ──paid──► AWAITING_PICKUP
AWAITING_PICKUP ──pickup──► RENTED ──finish/cancel──► AVAILABLE   [release path, Phase 3]
any ──admin──► MAINTENANCE ──admin──► AVAILABLE
```
Phase 3 implements the **release** transitions (`→ AVAILABLE` on `RentalFinished` /
`RentalCancelled` event, and via `LockerReconciliationJob`). The reserve/advance
transitions are wired in Phase 5 (Rentals); the aggregate methods exist now with
`@phase5`-tagged tests skipped.

## Entity: InventoryKit (`locations` module)

**Table**: `inventory_kits`

| Field | Type | Constraints / Default | Notes |
|---|---|---|---|
| `id` | uuid PK | — | |
| `station_id` | uuid FK → `stations.id` | NOT NULL | a kit belongs to a station |
| `locker_id` | uuid FK → `lockers.id` | nullable | nullable = unassigned (FR-030) |
| `name` | varchar(255) | NOT NULL | |
| `kit_type` | varchar(100) | NOT NULL | free-form label (e.g. `SUP_BOARD`, `PADDLE`) — key for tariff lookup (FR-029) |
| `created_at` | timestamptz | NOT NULL DEFAULT now() | |

**Invariants**:
- Reassigning `locker_id` (including to null) does not alter historical rentals that
  referenced the kit (FR-030) — historical rentals reference their own snapshot of
  kit type + locked price, not this row.
- No `deleted_at` — kits are deactivated by unassigning (`locker_id = null`), not
  deleted, to preserve audit history. (Soft-delete not required here; if a kit must be
  retired, set `locker_id = null` and stop creating tariffs for its type.)

## Aggregate: Tariff (`pricing` module)

**Table**: `tariffs`

| Field | Type | Constraints / Default | Notes |
|---|---|---|---|
| `id` | uuid PK | — | |
| `org_id` | uuid FK → `organizations.id` | NOT NULL | per-org (FR-028) |
| `kit_type` | varchar(100) | NOT NULL | matches `inventory_kits.kit_type` |
| `day_type` | enum `day_type` (`WEEKDAY`, `WEEKEND`) | NOT NULL | FR-023 |
| `duration_minutes` | integer | NOT NULL, CHECK > 0 | one admin-configured duration option (FR-024) |
| `price_minor` | integer | NOT NULL, CHECK >= 0 | minor units (Principle III) |
| `currency` | varchar(3) | NOT NULL DEFAULT `UAH` | |
| `created_at` | timestamptz | NOT NULL DEFAULT now() | |
| `deleted_at` | timestamptz | nullable | soft delete (FR-025, config data) |

**Uniqueness**:
```sql
UNIQUE (org_id, kit_type, day_type, duration_minutes) WHERE deleted_at IS NULL
```
A duplicate insert (same key, not soft-deleted) is rejected by the partial unique
index (FR-026); the repository maps the constraint violation to a
`DuplicateTariffError` returned as `Err(...)` from `TariffService.create`.

**Lifecycle**:
- Created → offered to renters (adds a duration option).
- Soft-deleted (`deleted_at = now()`) → duration option no longer offered; in-progress
  and completed rentals retain their locked price (FR-027). The partial unique index
  lets a new tariff with the same key be created after the old one is soft-deleted.

## Value Objects (in `shared-kernel`, referenced here)

- `Money(amountMinor: number, currency: string)` — used for `tariffs.price`.
- `OrgId`, `EntityId<T>` — typed IDs.
- `HaConnectionConfig` VO (new in `locations` domain): `{ urlOrIp: string, tokenRef:

  construction (`autoLockDelaySeconds > 0`, `urlOrIp` non-empty).

## Critical Indexes (from architecture §5.4)

```sql
-- Renter-facing station picker: bookable stations only.
-- is_active is the effective flag (admin_intended_is_active AND health_status != OFFLINE),
-- maintained as a regular column updated by the application on every health-status
-- transition (see "Effective Active State" above). The partial index predicate relies
-- on is_active already encoding the health-status condition.
CREATE INDEX idx_stations_bookable
  ON stations(org_id, is_active, is_visible_to_clients, sort_order)
  WHERE working_status = 'WORKING' AND deleted_at IS NULL;

-- Locker availability: only free lockers
CREATE INDEX idx_lockers_available
  ON lockers(station_id)
  WHERE status = 'AVAILABLE' AND current_rental_id IS NULL AND deleted_at IS NULL;

-- Tariff lookup by (kit type, day type) within an org
CREATE INDEX idx_tariffs_lookup
  ON tariffs(org_id, kit_type, day_type, duration_minutes)
  WHERE deleted_at IS NULL;
```
The `idx_stations_bookable` + `idx_lockers_available` pair is the backbone of the
< 2 s p95 renter-facing bookable-stations query (NFR).

## Bookability Rule (pure domain function)

`BookabilityRule.evaluate(station, locker, tariffsForToday): boolean` returns true iff
**all** of (FR-001):
1. `station.isActive === true`
2. `station.isVisibleToClients === true`
3. `station.workingStatus === 'WORKING'`
4. `locker.inventoryKit != null` (a kit is assigned)
5. `tariffsForToday.length > 0` (≥1 tariff for the kit's type + today's day type)
6. `locker.status === 'AVAILABLE'` (equivalently `current_rental_id IS NULL`)

This is a pure function over in-memory aggregates — no DB, no I/O — so it is unit-
tested exhaustively (each of the 6 conditions independently toggled). The renter-facing
query composes the two partial indexes above with a final in-memory filter through this
rule for defensive correctness (spec Error Scenarios: "Tariff lookup miss for a bookable
locker → remove from offered list").

## Cross-Module References

- `locations` references `organizations` (FK `org_id`), `shared-kernel` (`Money`,
  `OrgId`, `EventBus`, `Result`, `TenantContext`). No reference to `pricing`,
  `rentals`, `iam`, `notifications`, or `audit-log` at the module-import level —
  interaction with the latter three is event-driven only (Principle IV).
- `pricing` references `organizations` (FK `org_id`), `shared-kernel`. It is called
  synchronously by `rentals` (Phase 5) via `PricingService.quote()`; `locations` does
  not call `pricing`.

## Append-Only / Audit Notes

- `stations`, `lockers`, `inventory_kits`, `tariffs` are **config data** — soft-delete
  via `deleted_at` is permitted (architecture §5.1). They are not financial/audit
  tables; the append-only prohibition (Principle X) does not apply to them.
- Admin mutations to any of these tables are recorded in the `audit_log_entries`
  table (owned by `audit-log`, Phase 9) via the `@AuditableAction` decorator on the
  application-service methods (Constitution Principle X). The decorator is provided by
  `shared-kernel` (Phase 1); the `audit-log` subscriber is wired in Phase 9. In Phase 3
  the decorator is applied but its subscriber is a no-op log line until Phase 9.
